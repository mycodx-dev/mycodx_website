# 문의·채용 메일 표시와 운영 수신처 전환

## 변경된 표시

- 공개 문의/채용 폼의 접수 안내·완료·오류 문구를 한국어·영어·일본어·프랑스어에서 정리했습니다. 서비스명·메일 서버 접수 여부·임시 저장소 정리 설명을 방문자에게 표시하지 않습니다.
- 채용의 개인정보 동의와 1년 보관 안내는 유지합니다. 문의 개인정보 안내는 담당자 전달·답변이라는 이용 목적 중심으로 정리했습니다.
- 문의 완료·오류 화면과 메일 본문/제목에서 내부 UUID를 접수번호로 표시하지 않습니다. 내부 중복 방지와 Message-ID, X-Entity-Ref-ID는 유지합니다.
- 문의 메일: 문의 유형·작성자·소속·회신 이메일·한국 시간 접수 시각, 문의 본문.
- 채용 메일: 지원 분야·지원자·연락처·학력·경력·접수 시각, 지원 내용, 첨부 서류 종류·파일명·용량.
- 두 제공자 모두 같은 HTML 본문과 일반 텍스트 대체 본문을 사용합니다. 원본 첨부와 Reply-To는 유지하며, 외부 이미지·웹폰트·추적 리소스는 사용하지 않습니다. 입력한 HTML은 실행하지 않고 문자로 표시합니다.
- 제목 예: `[MycoDx 문의] 홍길동 · 연구 협력`, `[MycoDx 채용] 김지원 · 연구개발`. 테스트 모드에서는 `[TEST]`와 본문 테스트 안내를 유지합니다.

## 실제 메일함으로 바꾸기

이번 작업에서 원격 환경변수나 배포를 변경하지 않았습니다. 기존에 정한 운영 수신처는 문의 `info@mycodx.com`, 채용 `jakim@mycodx.com`입니다. 주소를 바꾸려면 아래 두 변수의 값만 변경합니다. 발신 계정과 수신 주소는 별개입니다.

Vercel 프로젝트 → Settings → Environment Variables에서 **실제 사용할 배포 환경**에 다음 값을 설정합니다. 대표 `vercel.app` 주소도 Production일 수 있습니다.

| 변수 | 운영 값/작업 | 유형 |
| --- | --- | --- |
| `CONTACT_TO` | `info@mycodx.com` | Config |
| `CAREERS_TO` | `jakim@mycodx.com` | Config |
| `MAIL_TEST_RECIPIENT` | **Production에서 삭제하거나 비워 둡니다.** 값이 있으면 위 두 수신처보다 우선하여 모든 문의·채용 알림이 테스트 메일함으로 갑니다. | Config |
| `MAIL_PROVIDER` | SMTP 사용 시 기존 `smtp` 유지 | Config |

`MAIL_TEST_RECIPIENT`가 Production·Preview 공용으로 등록되어 있다면 Production 적용만 해제하고 Preview에는 테스트 주소를 유지합니다. **Preview에서는 테스트 수신 주소가 필수**입니다. 두 실제 수신처를 등록했어도 테스트 변수가 남아 있으면 실제 담당자에게 가지 않습니다.

`SMTP_USER`와 `SMTP_PASS`는 발신 인증용입니다. 수신처를 변경하기 위해 이 값을 채용 담당자 계정으로 바꾸지 않습니다. `SMTP_USER=info@mycodx.com`이라면 발신자는 그 계정이고, 채용 수신자는 `CAREERS_TO`가 됩니다. 답장 버튼은 제출자가 입력한 이메일로 연결됩니다. 비밀번호와 키는 채팅이나 Git에 넣지 않습니다.

환경변수 저장 후 **새 코드 커밋·push → 배포 Ready 확인** 또는 해당 환경으로 재배포해야 적용됩니다. 기존 관리자 검색·소식 변경을 아직 배포하지 않았다면 [검색·소식 적용 안내](admin-search-news-setup.md)의 SQL을 먼저 적용합니다. 이번 메일 문구/서식 변경 자체에 추가 SQL은 없습니다.

## 전환 후 확인

1. 새로운 가상 문의 1건과 가상 채용지원서 1건을 제출해 각각 지정한 메일함으로 오는지 확인합니다. 실제 발송을 시작할 시점에 운영 수신처 전환을 진행합니다.
2. 제목에 `[TEST]`가 없고, 수신처·Reply-To·한국 시간·HTML 표·첨부 원본이 올바른지 확인합니다.
3. 실제 이카운트/Outlook/Gmail 메일 앱에서 서식을 확인합니다. 로컬 HTML 렌더링과 MIME 구성 테스트는 실제 메일 클라이언트 렌더링을 완전히 대신하지 않습니다.

이미 대기 중인 채용 알림은 접수 당시 수신처를 DB에 기록합니다. 수신처 전환 후 예전 테스트 알림을 새 운영 주소로 자동 재지정하지 않습니다. 이전 대기 알림은 `CONFIGURATION` 상태가 될 수 있으며, 무작정 재발송하지 말고 이력과 수신함을 확인합니다. 새 설정 검증은 반드시 새 가상 제출로 진행합니다.
