# 관리자 논문 관리 적용

`/admin`에 **논문 관리** 메뉴를 추가합니다. 기존 승인 관리자 계정으로 논문 추가·수정·임시저장·게시·비공개 전환이 가능합니다. 홈페이지 `/publications`의 연도별 디자인과 기존 PDF 링크는 유지합니다.

## 직접 적용할 순서

운영 Supabase, Vercel 환경변수 및 배포는 이 작업에서 변경하지 않았습니다.

1. Supabase → SQL Editor → New query → Role `postgres`에서 `supabase/migrations/202611050002_publications_cms.sql` **전체**를 실행합니다. 기존 채용 기본 SQL이 적용되어 있어야 합니다. 이 파일 하나로 테이블·권한·RPC와 현재 공개 중인 논문 2건을 준비합니다. 기존 채용/소식 SQL은 다시 실행하지 않습니다.
2. 별도 쿼리에서 읽기 전용 `supabase/verification/06_publications_verify.sql`을 실행합니다. 최초에는 논문 total=2, published=2, private_drafts=0입니다. 두 테이블 RLS=true, 모든 직접 테이블/컬럼/시퀀스 접근=false, RPC 5개의 anon/authenticated 실행=false, service_role 실행=true여야 합니다. 각 결과의 예상값은 SQL 주석에도 있습니다.
3. Vercel → 프로젝트 Settings → Environment Variables에 `PUBLICATIONS_CMS_ENABLED` = `true`를 추가합니다. **Type: Config**, **Environment: Production**. Preview에서 사용할 경우 해당 환경에도 별도 등록합니다. 기존 Supabase URL/키·관리자 계정을 재사용하며 새 비밀 키나 유료 서비스는 필요 없습니다.
4. 코드 커밋·푸시 후 Vercel 배포가 Ready인지 확인합니다. 환경변수를 기존 배포에 적용하려면 재배포가 필요합니다.
5. `https://mycodx.com/admin` → **논문 관리**에서 기존 2건을 확인합니다. `/publications`에서 제목·연도·설명·PDF 연결을 확인합니다.

커밋 메시지: `feat: 관리자 논문 관리 및 Supabase 공개 논문 목록 연동`

마이그레이션은 트랜잭션이며 재실행하면 `Already applied`로 중단됩니다. 기존 편집 내용을 덮어쓰거나 중복 생성하지 않습니다. 테이블을 삭제하거나 RLS를 끄지 마세요. 오류가 발생하면 다음 단계로 넘어가지 말고 확인합니다. SQL Editor의 쿼리 **Save**와 DB 실행 **Run**은 별개입니다.

## 사용 방법

- 논문 추가 → 발행 연도, 제목, 전체 저자, 학술지, 논문 링크를 입력합니다. MycoDx 참여 저자·권·논문 번호/페이지·DOI·설명은 선택입니다.
- 설명은 한국어·영어·프랑스어·일본어를 편집합니다. 해당 언어가 비어 있으면 영어, 한국어 순으로 표시합니다.
- DOI 입력란은 `10.1234/example` 형식입니다. DOI URL은 논문 링크 입력란에 넣습니다. 초안끼리, 공개본끼리는 같은 DOI(대소문자 무시)를 중복 사용할 수 없습니다. 중복되는 저장/게시 작업은 거부됩니다.
- 논문 링크는 HTTPS 학술지/DOI/PDF 주소 또는 기존 `/papers/파일명.pdf` 경로입니다. **PDF 직접 업로드는 이번 기능에 포함되지 않습니다.** 경로 입력만으로 새 파일이 생성되지 않습니다. 기존 이력서 비공개 버킷은 사용하지 않습니다.
- **임시저장**은 관리자에게만 보입니다. **게시**를 눌러야 홈페이지에 반영됩니다. 게시 중인 논문을 수정하고 임시저장해도 방문자에게는 이전 공개본이 유지됩니다.
- **비공개 전환**은 홈페이지 목록에서 제외하고 관리자 초안을 유지합니다. 영구 삭제는 제공하지 않습니다. 이미 내려받은 PDF나 별도 원문 링크까지 삭제되는 것은 아닙니다.
- 발행 연도 내림차순으로 표시하며 같은 연도에서는 내부 UUID 내림차순으로 정렬합니다. 공개 목록은 20건씩 ‘논문 더 보기’, 관리자 목록은 최근 수정순 20건씩 이전/다음으로 조회합니다.
- 두 관리자가 동시에 수정하거나 저장 응답이 유실되면 버전 충돌이 표시됩니다. 입력 내용은 유지됩니다. 필요한 내용을 별도로 보관한 후 **최신 저장본 불러오기**로 확인합니다. 저장 요청을 자동 재시도하지 않습니다.
- 이번 가져오기는 실제 `/publications`에서 사용하는 `researchPublications` 2건만 대상으로 합니다. 현재 화면에 쓰지 않는 과거 `paperRecords` 전체는 공개하지 않습니다.

## 권한과 오류 처리

기존 `recruit_admins.active=true` 계정이 채용·소식·논문을 모두 관리합니다. 논문 편집만 가능한 별도 권한은 추가하지 않습니다. 매 요청에서 인증된 사용자 UUID를 확인하고 각 쓰기/관리 RPC에서 활성 관리자 여부를 검사합니다. 클라이언트가 보낸 관리자 UUID는 사용하지 않습니다.

`publications_posts`와 `publications_audit_logs`는 RLS 활성화, 직접 접근 권한 제거, 서버 전용 RPC 방식입니다. Secret Key는 서버에서만 사용합니다. 감사 이력에는 작업·관리자 UUID·버전·시각을 남기며 본문·비밀키는 기록하지 않습니다. 새 테이블 두 개를 기존 DB 백업·복구 대상에 포함하세요. 기존 `/papers` 파일은 저장소, 외부 원문은 해당 원본 저장소에서 별도로 백업합니다.

`PUBLICATIONS_CMS_ENABLED`가 없거나 false면 공개 페이지는 기존 코드의 2건을 사용하고 관리자 쓰기는 비활성화됩니다. **true일 때 API/DB 오류가 발생하면 기존 논문으로 자동 복귀하지 않습니다.** 비공개 처리한 논문이 다시 공개되는 것을 막기 위해 오류·재시도를 표시합니다. true 사용 후 false로 되돌리면 옛 2건이 다시 표시될 수 있으므로 공개 여부를 확인한 뒤 전환합니다.

## 검증

`npm test`, `npm run lint`, `npm run build`로 코드 확인이 가능합니다. `tests/publications.integration.sql`은 **새로운 일회용 로컬 PostgreSQL DB 전용**입니다. 가짜 Supabase 스키마/역할을 생성하므로 운영 Supabase SQL Editor에서 실행하지 않습니다.

배포 후에는 기존 2건, 초안 미노출, 게시 반영, 수정 초안 미노출, 비공개 후 미노출, 모바일 관리자 화면을 확인합니다. 실제 운영에 테스트 논문을 게시할 필요는 없습니다. 새 테스트 논문을 임시저장 상태로 확인하거나 별도 테스트 환경을 사용하세요.
