# 관리자 비밀번호 변경

코드를 배포한 뒤 `/admin`에서 로그인 → **비밀번호 변경** → 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 입력 → **비밀번호 변경하기**를 누릅니다. 성공하면 로그인 화면으로 돌아가며 새 비밀번호로 다시 로그인합니다.

추가 환경변수, DB 마이그레이션, 유료 기능, 패키지 설치는 필요하지 않습니다. 홈페이지 문의·채용 메일 설정 및 이카운트 웹메일 비밀번호와는 별개입니다. 관리자 이메일과 Auth UUID, 허용 목록은 유지됩니다.

## 동작과 보안

- 기존 `POST /api/admin`에 `password:change` 작업을 추가합니다. 기존 Origin 검사, 전용 헤더, 서명된 HttpOnly 쿠키, Supabase 사용자 확인, 활성 관리자 허용 목록 검사를 그대로 적용합니다.
- 브라우저에서 대상 이메일이나 UUID를 지정할 수 없습니다. 세션에서 확인한 계정으로 현재 비밀번호를 재인증하고, 재인증한 UUID가 기존 사용자와 같은지 및 관리자 활성 여부를 다시 검사합니다.
- 새 비밀번호는 최소 12자, UTF-8 기준 최대 72바이트입니다. 공백 제거·정규화 없이 비교하며 동일 비밀번호, 확인 입력 불일치도 서버에서 거부합니다. Supabase 프로젝트의 더 강한 비밀번호 정책도 그대로 적용합니다.
- 재인증은 기존 로그인과 같은 IP·이메일·전역 제한을 공유합니다. 이메일과 IP는 원문 대신 해시로 제한 저장소에 기록됩니다.
- 비밀번호 변경은 Publishable Key와 재인증한 사용자 토큰으로 `PUT /auth/v1/user`를 호출합니다. 관리자 Secret Key로 인증 정책을 우회하지 않습니다. `current_password`도 함께 전달합니다.
- 비밀번호와 토큰은 로그·브라우저 저장소·채용 테이블에 기록하지 않습니다. 입력 값은 HTTPS 요청 중에만 사용하며 성공·실패 후 입력란을 비웁니다. Auth 반환 본문은 노출하지 않습니다.
- 성공하면 현재 사이트 쿠키를 삭제하고 기존 세션 및 재인증 중 생성한 임시 세션의 로그아웃을 요청합니다. 로그아웃 통신 오류가 발생해도 이미 성공한 변경을 실패로 표시하지 않습니다. 다른 기기의 모든 기존 JWT가 즉시 무효화된다는 보장은 하지 않습니다.
- 저장 요청의 응답이 유실되면 자동 재시도하지 않습니다. 결과 불확실 안내 후 로그인 화면에서 새 비밀번호로 확인하도록 안내합니다. 새 비밀번호 로그인에 실패하면 기존 비밀번호로 확인합니다.
- 소식 작성 중 변경 메뉴로 이동하면 기존 미저장 경고를 적용합니다. 변경 중에는 관리 메뉴와 로그아웃 버튼을 비활성화하여 중복 요청을 막습니다.

## 배포 후 확인

1. 승인된 관리자 계정으로 로그인하고 비밀번호 변경 메뉴를 엽니다.
2. 확인 입력 불일치, 잘못된 현재 비밀번호에 대한 안내를 확인합니다. 반복 인증 시도로 제한이 걸리지 않도록 최소한으로 테스트합니다.
3. 본인이 정한 새 비밀번호로 변경합니다. 비밀번호를 채팅·스크린샷·로그에 남기지 않습니다.
4. 성공 안내 및 로그인 화면 전환을 확인한 뒤 새 비밀번호로 로그인합니다.
5. 채용 목록과 소식 관리에 기존 권한으로 접근되는지 확인합니다.

이 기능은 로그인한 사용자의 비밀번호 변경입니다. 비밀번호를 잊었을 때 사용하는 이메일 복구 링크 처리 화면은 별도 기능이며 이번 범위에 포함하지 않습니다.
