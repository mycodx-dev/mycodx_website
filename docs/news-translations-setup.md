# 소식 다국어 번역 적용

소식 화면은 한국어·영어·프랑스어·일본어를 지원합니다. 선택한 언어의 번역이 비어 있으면 영어, 영어도 비어 있으면 한국어를 표시합니다. 자동으로 번역하지 않습니다.

2026-11-25 운영 API 확인 결과, 협약 소식(`/news/5`)은 네 언어가 반영되어 있습니다. 홈페이지 개설, KIMES BUSAN 2026, ICID 2026, CES 2027 소식은 프랑스어·일본어가 누락되어 있습니다.

## 운영 Supabase에 기존 소식 번역 반영

1. 운영 프로젝트의 **SQL Editor → New query**를 엽니다.
2. [`202611250003_news_fr_ja_translations.sql`](../supabase/migrations/202611250003_news_fr_ja_translations.sql)의 전체 내용을 붙여 넣고 `postgres` 역할로 **Run**을 누릅니다.
3. `/news/1`부터 `/news/4`까지 결과 행의 `fr_ready`, `ja_ready`가 모두 `true`인지 확인합니다. 게시 중인 글은 `draft`와 `published` 두 행, 비공개 글은 `draft` 한 행이 나옵니다.
4. 홈페이지의 프랑스어·일본어 소식 목록과 각 상세 페이지를 새로고침해 확인합니다. 예: `/news?lng=fr`, `/news/3?lng=ja`.

이 SQL은 네 글의 빈 프랑스어·일본어 제목·요약·본문과 대표 이미지 설명을 채웁니다. 한국어·영어, 이미 작성된 번역, 사진, 글 번호, 날짜·정렬, 게시 시각은 유지합니다. 초안과 공개본을 각각 수정하므로 미게시 변경 사항은 공개되지 않고 비공개 글도 공개되지 않습니다. 한국어 원문이 달라졌거나 대상 글이 없으면 전체 작업을 취소합니다. 오류가 나면 원문과 번역을 맞춘 뒤 적용해야 하며, 검사 조건을 삭제해서 실행하지 않습니다.

재실행해도 중복 반영하거나 이후 편집을 덮어쓰지 않습니다. 협약 글은 수정하지 않으며, 협약 번역 SQL을 다시 실행할 필요도 없습니다. 협약 번역이 아직 없는 다른 환경은 [협약 소식 안내](changwon-mou-news-setup.md)를 참고합니다.

**공개 소식의 번역은 SQL 실행 후 바로 반영되며 별도 배포가 필요 없습니다.** 테이블·권한·Storage·환경변수 추가 설정도 필요 없습니다. `src/content/news.json` 수정이나 코드 배포만으로는 기존 Supabase 게시글이 바뀌지 않습니다.

## 이후 소식 작성·수정

이번 코드 변경을 배포하면 `/admin`의 소식 편집창에서 네 언어의 제목·요약·본문, 대표 이미지 설명, 추가 사진 설명·캡션을 입력할 수 있습니다. 본문 미리보기에서도 언어를 선택할 수 있습니다.

각 언어 내용을 입력하고 **임시저장 → 게시**하면 홈페이지에 반영됩니다. 한국어만 수정해도 다른 언어의 기존 내용은 유지되므로, 원문 변경 시 번역도 함께 확인합니다.

## 검증

빌드와 기존 소식·관리자 테스트 8개, 관리자 편집 파일의 ESLint 검사를 통과했습니다. 별도 임시 PostgreSQL에 운영 공개본을 복제하여 네 글의 번역 반환, 한국어·영어·기존 번역·날짜·정렬·사진 보존, 협약 글 유지, 미게시 초안 분리, 비공개 유지, 재실행 및 원문 변경·대상 누락 시 전체 롤백을 확인했습니다.

브라우저에서는 임시 DB의 공개 API 결과를 모의 응답으로 사용해 네 언어의 목록과 상세 페이지를 PC·모바일에서 확인했습니다. 관리자도 모의 API로 네 언어 입력·미리보기·저장을 검증했습니다. 이번 작업에서 운영 DB 변경이나 배포는 수행하지 않았습니다.
